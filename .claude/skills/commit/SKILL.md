以下のコミットガイドラインに従い、現在の変更をコミットしてください。

## 手順

1. **状態確認**: `git status` で現在の状態を確認する（コンフリクトや rebase 中なら中断してユーザーに報告する）
2. **変更内容の把握**: `git diff`（未ステージ）と `git diff --staged`（ステージ済み）を確認する
3. **直近のコミット確認**: `git log --oneline -5` でメッセージのスタイルや文脈を把握する
4. **ブランチ確認**: 現在のブランチが `main` の場合、先にブランチを切るようユーザーに確認する
5. **分割判断**: 変更が複数の論理的なまとまりに分かれるか判断する（後述の分割ガイドを参照）
6. **ステージング**: 必要に応じて `git add <file>` や `git add -p` で対象を選択する。`git add .` は単一の論理変更であることを確認した場合のみ使用する
7. **コミット作成**: 以下のルールに従ってコミットメッセージを書く
8. **分割コミットの場合**: 手順 5〜7 を残りの変更に対して繰り返す

### ステージ済みの変更がない場合

- 未ステージの変更がある → 何をコミットするかユーザーに確認する
- 変更自体がない → その旨をユーザーに伝えて終了する

## コミット単位のルール

- 1コミット = 1つの論理的変更。複数の関心事を1コミットに混ぜない
- 機能変更とリファクタリングは必ず別コミットにする
- すべてのコミットでビルドが通る状態を維持する
- 変更が複数の論理的なまとまりに分かれる場合は、分割してコミットする

### 分割の目安

| 変更の種類 | コミット粒度 |
|---|---|
| 機能追加 | 1ユースケース / 1エンドポイント単位。大きい場合はドメイン層→アプリケーション層→アダプター層の順に分割 |
| リファクタリング | リネーム、メソッド抽出、依存関係の変更などを個別に |
| バグ修正 | 1バグ1コミット。失敗テスト追加と修正を分けてもよい |
| 設定・インフラ | 依存追加、CI変更、Docker変更などはそれぞれ独立 |
| テスト追加 | テスト対象の機能単位でまとめる |

## コミットメッセージのルール

- Conventional Commits に従い、**日本語**で記述する
- 形式: `type(scope): 概要`
- `git commit -m "タイトル" -m "本文"` の形式を使う（trailer も `-m` で追加）

### 1行目（タイトル）

- 50文字以内を目安
- 何を変えたかを簡潔に書く
- 例: `feat(expense): 経費カテゴリの一覧取得APIを追加`

### 本文（必要な場合のみ）

- 「なぜ」その変更をしたかが自明でない場合に理由を書く
- 技術的な判断の背景があれば記載する

### type 一覧

| type | 用途 |
|---|---|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `refactor` | リファクタリング（振る舞いの変更なし） |
| `test` | テストの追加・修正 |
| `docs` | ドキュメントのみの変更 |
| `chore` | ビルド設定、依存更新など |
| `style` | フォーマット変更（コードの意味に影響しない） |

### scope

- 変更対象のモジュールやレイヤーを記載する（例: `expense`, `api`, `auth`, `infra`）
- 対象が広範囲で特定しにくい場合は省略可

### Breaking Change

- 後方互換性のない変更には `!` を付与する: `feat(api)!: レスポンス形式をProblemDetailに統一`
- 必要に応じて本文に `BREAKING CHANGE: 説明` を記載する

## 禁止事項

- `.env`、クレデンシャル、シークレットを含むファイルはコミットしない
- 確認なしに `git add .` で全ファイルをステージしない

## Trailer

AI エージェントが作成したコミットには、実行主体に対応する trailer を付与する。
実行主体と異なる trailer は使用しない。

| 実行主体 | trailer |
|---|---|
| Claude Code | `Co-authored-by: Claude <noreply@anthropic.com>` |
| Codex | `Co-authored-by: Codex <codex@openai.com>` |

実行主体が上記以外、または判別できない場合は、ユーザーに確認してから trailer を付与する。
